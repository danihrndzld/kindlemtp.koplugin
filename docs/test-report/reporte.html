    Objeto y base de prueba

    kindlemtp_core.lua arranca y detiene el responder MTP del Kindle (tizen-mtp) mientras KOReader corre: valida el equipo (7 checks), busca el destino D-Bus, ejecuta la receta de docs/design.md (reset, startMtp, señal driveModeStateChanged unicast, stopMtp + mtp.sh udc disable), guarda el marcador /tmp/kindlemtp.active compartido con KOBridge y restaura preventScreenSaver. Todo efecto pasa por un env inyectado; las pruebas usan spec/fake_env.lua, que registra cada comando en orden.

    Los esperados salen de la spec. Ejemplos literales: 'The drive-mode signal must be unicast'; 'After 20 s without a host it stops quietly and returns timeout'; 'stop(): idempotent from every state, whoever owns the marker: stopMtp 1, then mtp.sh udc disable'. Donde la spec calla se declararon los supuestos S1-S8.

    Fixtures: ListNames, GetConnectionUnixProcessID, el error de dbus-send (en stderr, stdout vacío), /proc/<pid>/stat de volumd (T) y tizen-mtp (S), 60 líneas de syslog de una corrida 4→1→2→3→4 sin debug y la cinta UDC con host se capturaron en el Paperwhite el 2026-10-16. Quedan sintéticos listnames_without_mtp.txt (la captura sin la línea de com.lab126.mtp), getpid_other.txt y la cinta de cargador; spec/fixtures/README.md da el origen de cada archivo.
